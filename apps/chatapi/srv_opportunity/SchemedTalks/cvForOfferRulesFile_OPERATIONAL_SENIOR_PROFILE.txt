JEU DE RÈGLES COMPLET DE GÉNÉRATION DE CV CIBLÉ
VERSION : OPERATIONAL_SENIOR_PROFILE

Toutes les règles définies dans le "Jeu de règles par défaut complet de génération de CV ciblé pour une offre" s’appliquent intégralement.
Les règles suivantes constituent une SURDÉFINITION EXPLICITE et doivent être appliquées en priorité
lorsqu’elles précisent ou restreignent le comportement de génération.

=====================================================================
SURDÉFINITION — CALIBRATION DU PROFIL ATTENDU
=====================================================================

Objectif de cette calibration :
Générer un CV ciblé correspondant à un profil de développeur / ingénieur logiciel senior
à forte dominante OPÉRATIONNELLE, attendu pour des missions de conception, implémentation,
maintenance, correction et optimisation continue de solutions existantes.

Ce profil n’est PAS un rôle d’architecte transverse, de responsable de plateforme,
ni de lead stratégique, même si le candidat possède par ailleurs ces compétences.

---------------------------------------------------------------------
POSTURE GLOBALE À ADOPTER
---------------------------------------------------------------------

- Le CV doit refléter un professionnel senior impliqué directement dans le code,
  les correctifs, les évolutions fonctionnelles et la qualité logicielle au quotidien.
- Le ton doit être pragmatique, concret et orienté delivery.
- Les formulations doivent privilégier l’action et l’exécution.

Verbes à privilégier :
  implement, develop, maintain, fix, optimize, integrate, refactor, debug, test, deploy

Verbes à limiter ou contextualiser :
  architect, define strategy, design global architecture, lead organization-wide initiatives

---------------------------------------------------------------------
HIÉRARCHISATION DES EXPÉRIENCES
---------------------------------------------------------------------

- Mettre en avant en priorité :
  - développement back-end PHP
  - intégration API REST
  - maintenance corrective et évolutive
  - optimisation de performances
  - CI/CD et qualité logicielle
  - intégration front-end Angular côté consommation d’API

- Les expériences très transverses (orchestration, plateformes génériques, R&D, moteurs)
  peuvent être mentionnées UNIQUEMENT si elles apportent un bénéfice direct
  à la compréhension du rôle opérationnel du candidat.

- Les expériences de type produit, framework, moteur ou plateforme doivent être :
  - soit fortement résumées,
  - soit repositionnées comme support technique à des besoins opérationnels concrets.

---------------------------------------------------------------------
RÈGLES SPÉCIFIQUES POUR LA SECTION "OBJECTIVES"
---------------------------------------------------------------------

- L’objectif professionnel doit :
  - correspondre explicitement à un poste opérationnel
  - éviter toute formulation de type "architecte de solutions globales"
  - souligner la capacité à s’intégrer rapidement dans une équipe projet existante

---------------------------------------------------------------------
RÈGLES SPÉCIFIQUES POUR LA SECTION "SKILLS"
---------------------------------------------------------------------

- La section skills doit être :
  - directement alignée avec les compétences demandées dans l’offre cible
  - factuelle et outillée (technos, frameworks, pratiques)

- Ne pas sur-pondérer :
  - les axes transverses,
  - les compétences de conception globale,
  - les approches de type plateforme générique.

- Distinction explicite des niveaux de compétences :

  - Les compétences centrales correspondent aux technologies
    sur lesquelles le candidat est immédiatement productif
    dans le cadre principal du poste.

  - Les compétences secondaires ou environnementales correspondent
    aux technologies :
      - explicitement mentionnées dans l’offre cible,
      - présentes dans le Super CV,
      - mais non centrales dans le positionnement principal du profil.

- Les compétences secondaires ou environnementales DOIVENT être mentionnées,
  sous une forme maîtrisée et non dominante, afin de refléter fidèlement
  l’écosystème technique du poste sans créer de décalage de posture.

- Ces compétences :
  - ne doivent pas apparaître dans le titre du CV,
  - ne doivent pas redéfinir l’objectif professionnel,
  - ne doivent pas supplanter les compétences centrales,
  - peuvent être regroupées dans une sous-catégorie dédiée
    (ex : "Écosystème technique", "Langages et environnements connexes").

---------------------------------------------------------------------
RÈGLES SPÉCIFIQUES POUR LA SECTION "EMPLOYMENT"
---------------------------------------------------------------------

- Pour chaque expérience :
  - mettre en avant les tâches concrètes réalisées
  - limiter les descriptions de vision, roadmap ou gouvernance
  - privilégier ce qui est directement réutilisable dans un contexte client ESN ou projet interne

- Les responsabilités de management doivent être mentionnées sobrement
  et ne jamais devenir le point central de l’expérience.

- appliquer les régles par défaut pour les compétences demandées dans l'Offre Cible.

---------------------------------------------------------------------
CONTRAINTE FINALE DE COHÉRENCE
---------------------------------------------------------------------

Le CV généré doit donner au recruteur l’impression que le candidat est immédiatement
opérationnel sur le poste proposé, sans risque de surqualification perçue ou
de décalage de posture.

Aucune compétence, technologie ou expérience ne doit être ajoutée si elle n’est
pas strictement déductible du Super CV et de l’offre cible.

=====================================================================
FIN DE LA SURDÉFINITION
